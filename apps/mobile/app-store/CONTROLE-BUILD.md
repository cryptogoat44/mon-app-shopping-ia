*Chantier 8, point 8 de la feuille de route V1. Pour le fondateur. Relue le 21 novembre 2026 sur le code de `main` (0474313). À refaire **à chaque** build envoyé à la validation d'Apple. ## A. Le code du build

- [ ] **Le lecteur intégré : décision prise pour ce build.** La mission « liens vidéo » a remis le lecteur officiel TikTok / Instagram et « Spotter ce moment » (instantané de la vue seulement, `WKWebView.takeSnapshot`), **allumés par défaut** (règles 5.2.2, 5.2.3 et 2.5.19 : décision du fondateur à confirmer avant tout envoi ; ce qu'elle change pour Apple : [NOTES-VALIDATION.md](NOTES-VALIDATION.md), partie 1, point 11, et [CONFIDENTIALITE-APPLE.md](CONFIDENTIALITE-APPLE.md), partie 6).

Pour un build sans lecteur : les deux à `false` (le module natif `apps/mobile/modules/spotto-player-snapshot` n'est alors pas relié à l'app : `plugins/lecteur-integre.js`). Le serveur peut couper un lecteur après coup, jamais en allumer un absent du build (`apps/mobile/BUILD-IPHONE.md`, section 9).
  Un test vérifie à chaque passage que le module ne fait que l'instantané (ni ReplayKit, ni PDF, ni téléchargement : `apps/mobile/tests/player-access.test.ts`).
- **Les liens TikTok et Instagram : rien à vérifier dans le code.** Un lien collé ou partagé ouvre l'écran « vidéo partagée » (`apps/mobile/src/lib/link-step.ts`) ; ni l'app ni le serveur principal ne téléchargent quoi que ce soit de TikTok ou de Meta, et un test du serveur le revérifie à chaque passage (`apps/backend/tests/aucunMediaTiktokInstagram.test.ts`). Seul le service vidéo séparé peut récupérer une vidéo publique, et seulement si l'analyse d'un lien est allumée chez Render (partie C).
- [ ] **L'essayage virtuel n'est pas dans l'app** (il n'existe que sur le site ; règle 2.5.19 : aucune fonction cachée ou dormante). La fin doit dire « Conforme : rien de l'essayage dans le paquet iPhone ; tout est dans le site. » GitHub ne lance pas ce contrôle (il lance seulement le test `apps/mobile/tests/tryon-web-only.test.ts`, sur le code).

## B. Chez Expo (expo.dev → Spotto → Environment variables, environnement « production »)

- [ ] `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` (clé **publique**), `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_WEB_URL` : remplies (`apps/mobile/BUILD-IPHONE.md`, section 2). Le contrôle du début de build arrête un build qui en manque une, ou dont l'adresse n'est pas celle de **spotto-prod** — base de test spotto-dev-2 comprise (`apps/mobile/scripts/verifier-build.js`). Une clé `sb_publishable_…` ne dit pas son projet : vérifiez vous-même qu'elle vient de spotto-prod.
- [ ] `EXPO_PUBLIC_ENVIRONMENT` = `production`.
- [ ] **Les 5 réglages de l'éditeur** `EXPO_PUBLIC_PUBLISHER_NAME`, `_STATUS`, `_ADDRESS`, `_EMAIL`, `_PHONE` : remplis. Sans eux, les pages légales de l'app affichent « [À compléter] » (refus d'Apple, règle 2.1) et « Nous contacter » disparaît (`apps/mobile/src/lib/contact.ts:37`). Depuis le lot « conformité Apple », le contrôle du début de build **arrête** un build `production` où l'un des cinq manque, et le nomme (pour `preview`, il prévient seulement). Il ne juge pas le contenu : relisez vous-même les cinq valeurs.
- [ ] **Plus aucun passage entre crochets dans les textes légaux** (`apps/mobile/src/legal`) : « [À compléter », « [À vérifier », « [À décider » et leurs équivalents anglais. Pour savoir où vous en êtes sans lancer de build : `cd apps/mobile && EAS_BUILD_PROFILE=preview node scripts/verifier-build.js` (lisez la ligne « Textes légaux inachevés » ; il se plaint aussi des réglages absents de votre Mac, c'est normal : ils ne sont saisis que chez Expo). Ce contrôle ne voit ni le bandeau « Projet » des pages légales, ni les pages du site en ligne : voir la partie F.
- [ ] **Sentry** : `EXPO_PUBLIC_SENTRY_DSN` rempli, `SENTRY_AUTH_TOKEN` en **Secret**, et **pas** de `SENTRY_DISABLE_AUTO_UPLOAD` dans l'environnement production (`apps/mobile/BUILD-IPHONE.md`, section 3).

## E. Le compte de démonstration

Pas de script : chaque pièce du Vault, des Envies ou d'une publication exige une photo, et un script aurait demandé la clé secrète de production sur le Mac. Dans l'app, c'est dix minutes, avec du vrai contenu.

**Le créer (une fois, puis après chaque validation : Apple essaie souvent la suppression du compte)** :
1. Une adresse e-mail que vous lisez, propre à Apple (par exemple un alias de votre messagerie). **Jamais** votre compte administrateur : sa suppression est refusée (`apps/backend/src/routes/account.ts:241`), et Apple essaie la suppression.
2. Dans l'app (build TestFlight), « Commencer » → inscription → confirmer l'e-mail → choisir un nom d'utilisateur.
3. Un mot de passe fort, gardé dans votre gestionnaire de mots de passe. **Jamais** dans ce dépôt, ni dans un e-mail.
4. Du contenu : 2 ou 3 recherches réussies (elles remplissent « Récemment spottées »), 2 ou 3 pièces gardées (Envies), 2 ou 3 pièces dans le Vault, 1 ou 2 publications.
5. Un **second compte, « l'ami »**, créé de la même façon, avec une publication **publique** et un commentaire. Les deux comptes **se suivent l'un l'autre** : l'onglet « Abonnements » du fil n'affiche que ses propres publications et celles des comptes suivis (`apps/backend/src/routes/posts.ts`), et deux comptes qui se suivent sont « amis » (`apps/backend/src/lib/messaging.ts:1-12`). Avec lui, préparez ce que les notes annoncent :
   - une **conversation ouverte**, avec au moins un message **reçu** par le compte de démonstration (écrit depuis le compte ami) : le testeur pourra essayer « ••• » → « Signaler » ;
   - une **collection montrée aux amis** dans le compte ami (deux ou trois envies) : le testeur pourra l'ouvrir depuis son profil et la signaler ;
   - une collection dans le compte de démonstration lui-même.
6. Un **troisième compte**, que le compte de démonstration ne suit pas : il lui envoie **une invitation** (un premier message), laissée sans réponse. Le testeur la trouvera dans Activité → Messages → « Invitations », et pourra l'accepter, la refuser ou bloquer. Ce compte publie aussi **une photo publique** : c'est elle que le testeur verra dans Fil → « Pour vous » (contenu d'un inconnu, à signaler ou bloquer). « Pour vous » ne montre que des publications publiques avec photo de moins de 14 jours, d'un compte public inscrit depuis plus de 24 heures, réglage « Proposer mon compte aux autres membres » allumé (comme au départ) (`apps/backend/src/lib/forYou.ts`) : créez ce compte au moins la veille, et republiez une photo si la dernière a plus de 14 jours le jour de l'envoi.
7. Le testeur pourra ainsi signaler et bloquer. Chaque signalement du testeur vous enverra une alerte : traitez-le, puis rétablissez le contenu si besoin. **Après chaque passage d'Apple, refaites le scénario** : l'invitation a pu être refusée (aucune nouvelle invitation pendant 30 jours : prenez alors un autre troisième compte), un compte bloqué, un message signalé, la publication de « Pour vous » signalée (pour le compte de démonstration, elle n'y reviendra jamais : publiez-en une nouvelle depuis le troisième compte).

**À chaque envoi :**
- [ ] Le compte se connecte (e-mail confirmé, mot de passe juste, pas suspendu).
- [ ] Il n'est pas administrateur : pas d'entrée « Modération » dans ses Réglages (`apps/mobile/src/app/(app)/settings.tsx:253`).
- [ ] Il a du contenu : Vault, Envies, une collection, publications ; lui et le compte ami se suivent l'un l'autre.
- [ ] La conversation avec le compte ami contient un message reçu, et l'invitation du troisième compte est en attente (Activité → Messages).
- [ ] Fil → « Pour vous » montre la publication du troisième compte (moins de 14 jours).
- [ ] **Il passe le contrôle anti-robots** : sur le build envoyé, déconnectez-vous, puis reconnectez-vous avec ses identifiants, si possible sur un autre réseau que le vôtre (4G). La connexion doit passer sans que le widget anti-robots bloque (`apps/mobile/ANTI-ROBOTS.md`). Le testeur d'Apple se connecte depuis ses propres réseaux : si la protection est activée dans Supabase et le bloque, il ne peut pas entrer, et l'app est renvoyée (Apple : « Provide App Review with full access to your app. »). En cas de doute, essayez aussi l'inscription d'un compte jetable.
- [ ] Il lui reste des recherches : ne l'utilisez pas le jour de l'envoi ; le compteur du jour repart à minuit, celui du mois (100) le 1er, heure de Paris.
- [ ] Ses identifiants sont dans les cases « Identifiant » et « Mot de passe » d'App Store Connect, et dans les crochets des notes.
